# 职业原子库 · 索引

> 原子库是整套诊断体系的**弹药**。所有涉及"目标岗位到底要什么能力"的判断，一律先查这里。
> 查不到 → 标 `〔须核实〕` → 向学生追问或让用户补充。**严禁临场用常识补。**

---

## 使用规则

### 三步查询法
1. 拿到学生的目标职业 → 在本文件的"原子登记表"里按职业名/别名检索
2. 命中 → 读该原子的**第 5 节（能力→证据对照表）**，用它去筛学生的履历
3. 未命中 → 在登记表底部"未命中记录"追加一行，诊断照常进行但全部相关判断标 `〔须核实〕`，并在报告末尾写入"建议优先补采该职业原子"

### 成熟度纪律（硬约束）

| 成熟度 | 能否用于评级 | 能否用于提问 |
|---|---|---|
| 骨架 | ✗ 严禁 | ✓ |
| 待校验 | ✓ 但须在报告中注明信息源 | ✓ |
| 已校验 | ✓ | ✓ |

**每份诊断报告需记录本次引用了哪些原子及其成熟度等级。**

|---|---|---|---|---|
| G-001 | 证据分级法 | 区分"参与"与"负责"，给经历打 L0—L4 级 | 已校验 | 0 |
| G-002 | 成果数字四问 | 把经历逼出可量化成果（规模/位次/增量/去向） | 已校验 | 0 |

| G-005 | 材料审核清单 | 七道闸审一份已成稿材料，输出保留/重写/删除；默认动作为**删除** | 已校验 | 0 |
| G-006 | 生涯发展报告结构模板 | 成长赛道三章骨架、模块清单、四素材桶、成果表述公式、**备选职业模块** | 已校验 | 0 |
| G-007 | 推演标注法 | 学生没说到的地方能补到什么程度、必须怎么标；★**唯一允许推演的场景** | 已校验 | 0 |

> **四个制作类原子的分工**：G-004 管**做事的先后**（防顺序错白做），G-005 管**成品的去留**（防包装过度），G-006 管**结构**（防把字数投进低分格子），G-007 管**没说到处的补齐**（防学生原样提交 AI 编的内容）。
> G-004 与 G-005 构成一个环：G-005 判出"需要回去补一件真事"时，退回 G-004 重排。
> G-006 与 G-007 构成 Step 8 的主轴：先把位置摆对，再把空的地方标清楚。

> **L × P 交叉使用**：G-001 管"你做了多少"，G-003 管"谁证明了"。
> 只有 **L≥2 且 P≥3** 的经历，才可作为某指标的正式证据。二者缺一不可。

## 待采集队列 ⚠️ 第一批优先级来源

> 来源：调研报告中**经高校官方新闻或主流媒体公开发报道**的历届金奖选手职业目标（第一至三届，共 38 条）。教育部官方名单一律不含职业目标字段，这些来自公开媒体。
>
> **这是最有价值的第一批原子**，因为它们是真实打穿过国赛评审的职业目标。

## 投喂格式

用户可以随时补充职业知识。四种投放方式都接受：

1. **完整原子**：直接按 `_原子模板.md` 填写，投喂后由 Agent 存入 `atoms/职业原子/` 并登记本索引
2. **零散职业知识**：丢一段文字/JD截图/访谈记录，Agent 负责拆成结构化原子并标"待校验"
3. **批量JD**：一次给多个同岗 JD，Agent 提炼共性任职要求
4. **纠错**：指出某个原子某项错误，Agent 更正并调整成熟度

**无论哪种方式，来源必须登记。** 无来源的知识一律降级为"骨架"。
