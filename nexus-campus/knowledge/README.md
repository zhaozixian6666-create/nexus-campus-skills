# 知识包

## 这里放什么

`capabilities/` 回答"怎么判断"，`knowledge/` 提供判断的**依据**。

| 放这里 | 不放这里 |
|---|---|
| 可查证的方法、标准、规则 | 判断结论（那是 capabilities 的事） |
| 结构模板（简历、PPT、答辩稿） | 通用鸡汤 |
| 具体案例（真事、有数字、有结果） | 网上的故事 |
| 图表、清单、对照表 | 从别处抄来的段落 |

**一条硬规矩**：知识包里每一条，都要能回答"这条从哪来的"。来源不明的，不进来。
**思想层多一道**：来源登记了但没点头认可的，也不进来。

## 五层知识包

```
knowledge/
├── 制度/        9 份。客观规则：学籍、绩点、保研、考研、出国、就业、科研、奖助
│   └── 讲「规则怎么规定、窗口什么时候关、去哪查」
├── 认知/        11 个认知主题，讲「为什么」「值不值」
│   └── 00_主题总表.md
├── 竞赛/        4 份。客观事实库。讲「哪个赛、什么规则、什么时候」
├── 赚钱/        副业红线与防骗清单
├── 思想/        3 份。唯一存放「本人认可的观点」的地方
│   ├── 00_思想原子导航.md —— 怎么学、两档措辞、六条纪律
│   ├── 01_思想原子卡.md —— 观点原文（统一生成，勿手改）
│   └── 02_问题-原子对照表.md —— 卡点信号 → 取哪条 → 拆什么
└── 原子库/      **可调用的知识库引擎**：50 条原子 + 216 条语料的数据、索引、检索脚本、调用契约
    ├── SKILL.md —— 触发条件、状态门禁、输出契约
    ├── data/ —— atoms.jsonl / corpus.jsonl / 00_索引.md（统一生成，勿手改）
    ├── scripts/query.py —— 按主题／层次／场景／关键词／出处检索
    └── references/调用契约.md —— 状态门禁、归属措辞、什么算答完
```

**制度层和竞赛层是同一类：客观事实，可查原文，不是任何人的观点。** 它们的价值在于"问什么都能给出能落地的东西"——没有这两层，库里全是"怎么想"，问到具体的"我这个情况还来得及吗"就答不上来。

**思想层是反过来的一类：它是观点，不是依据。** 它不回答"规定是什么""凭什么这么说"，只提供**拿什么立场去看一件事**。学生可以整份读来学；也可以卡住时取一条换个角度，取完必须落回 `capabilities/` 给结论。调用动作在 `../method/14_思想校准.md`。

**原子库层是引擎，不是文档**：思想层是它的精选卡（按卡点信号取一条），原子库层负责**全量检索、查出处、查库存**。状态门禁写在检索脚本和数据里——只有 ✅ 已认可的观点有原文，未认可与待确认的连数据层都进不去。取完必须落回 `capabilities/` 给结论。

**归属要分开**：本人认可并留有记录的口述判断，可以说"我一直这么说"；本人点头认可、从公开出版物提炼的判断，**必须标出处（作者 + 书名）**，说"这是从 X《Y》里提炼、我认可的一条"，不冒充原创、不说成自己的原话。卡片上每条都带「来源」与「认可状态」，和原子库一致。两档都不得拿去回答规则题。


### 11 个主题

| 主题 | 这一块回答什么 |
|---|---|
| 资源分配与个人定价 | 名额、资格、机会怎么分；你的时间和能力值多少钱 |
| 意义与选择 | 为什么读大学、要成为谁、每个选择的代价 |
| 表达与个人IP 表达与个人 IP | 在学校里怎么被看见 |
| AI时代的学与做 AI 时代的学与做 | AI 怎么改学习和做事，什么能力更值钱 |
| 概念澄清与思维 | 内卷、躺平、绩点、保研这些词到底在说什么 |
| 大学案例复盘 | 真实的人和赛，可复用的做法 |
| 中国大学制度 | 保研考研编制学历通胀，规则在哪 |
| 拖延与执行力 | 知道该做却做不到，卡在哪 |
| 学历投资与回报 | 读书值不值、大学是消费还是投资 |
| 榜样与模仿 | 该学谁、学他哪一层 |
| 人际识别 | 识人、边界、套路与反套路 |

**这 11 个主题不是按学科分的，是按学生真正会问出口的那句话分的。** 主题越贴近他原话，越容易被用上；按学科分（教育学、心理学、经济学），他一个都不会点开。

## 命名规则

```
<两位数字>_<中文名>.md
```

例：`制度/03_保研.md`、`制度/07_科研与竞赛.md`。

三条：

1. **层靠目录区分**，文件名不用再带层代号——`制度/03_保研.md` 一看就知道是制度层的第三份
2. **数字用两位**（01 / 02 …），否则 10 会排在 2 前面
3. **一个主题一份文件**，不要把七八件事塞进一份。塞进去的结果是三个月后自己都找不到

## 每份文件的结构

```markdown
# 主题

> 一句话说明这份文件解决什么

## 一、核心内容
（方法 / 标准 / 规则，分条写）

## 二、怎么用
（在什么情况下查这份，查完怎么落到动作）

## 三、来源
（每条内容标：本人判断 / 查证事实 / 转述他人）
```

**第三节不能省。** 没有来源的知识，等于没有知识。

## 这一层有什么

**制度 9 份** · **认知 11 个主题 + 总表** · **竞赛 4 份**

装的是「大学这个系统怎么运作」：规则怎么定、绩点怎么算、保研什么条件、竞赛怎么分档、一件事值不值得做。

- `制度/` 9 份，客观规则。每份都有「数据边界」（哪些会变）和「必须自查的变量」（去哪查）
- `认知/` 11 个主题，每个是一份独立知识包，七节固定（写法见下）
- `竞赛/` 4 份：总览（分档规则 + 全年时间轴）、Ⅰ 类、Ⅱ 类、其余榜单赛事简表

### 判断层不在本目录

`knowledge/` 装的是「大学这个系统怎么运作」。另一层东西在隔壁：

| | `knowledge/` | `judgement/` |
|---|---|---|
| 内容 | 认知 11 主题 + 竞赛 4 份 + 制度 9 份 | 260 条判断，都落在大学场景里 |
| 从哪来 | 客观规则（可查原文）+ 团队实践与方法沉淀 | **团队判断**，讲换处境还成不成立 |
| 能不能当依据 | **能**（规则查原文，判断带边界） | **不能**，只能当参考视角 |

**为什么不放进来**：放进来就会被当成「库里的判断」，讲的时候分不清哪句是方法、哪句是条件。物理隔开，调用时才不会混。

判断层的入口是 `../judgement/00_索引与用法.md`，那里写了这一层是什么、不是什么、怎么查。

### 认知层的写法（这是全库的标准）

每个主题都是一份独立知识包，七节固定：

| 节 | 写什么 |
|---|---|
| 一、问题界定 | 先把词拆开，剔掉假问题 |
| 二、机制 | 为什么会这样 |
| 三、判断标准 | 可操作、可验证、有阈值 |
| 四、反例与边界 | **这套什么时候不成立** |
| 五、这类问题上的判断 | 这一类问题上的明确立场 |
| 六、不覆盖什么 | 这一页讲不到的地方，以及为什么讲不到 |
| 七、和其他主题的关系 | 在体系里的位置 |

**第四节不能省。** 只讲「成立」不讲「边界」，就是把判断变成了教条。

**第六节也不能省。** 一个不说自己讲不到哪的系统，等于在骗人。

### 引用纪律

事实型内容（制度、竞赛）每一条都要能指到出处，引用时必须提醒「以本校当年文件」「以当届官网通知」为准。赛事时间、政策条款这类东西半年就过期，写成永久事实会害人。

规则写错比判断说浅更严重——说浅只是不够打动人，写错会让他按错的规则准备一年。
