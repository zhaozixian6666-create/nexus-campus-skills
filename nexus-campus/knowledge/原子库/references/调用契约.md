# 原子库引擎 · 调用契约

> 这份是给**调用方**看的细则：什么时候取、取几条、怎么说、取完交给谁。
> 入口是引擎的 SKILL.md，数据层、检索脚本与四张索引都在同一个目录下，按 README 的目录树找。

---

## 一、状态门禁（写在数据里，不靠提示词）

| 状态 | 条数 | 数据层有没有观点原文 | 引擎能不能返回 | 对外怎么说 |
|---|---|---|---|---|
| ✅ 已认可 | 18 | 有 | 可以 | 口述档「我一直这么说」；出版物档标作者 + 书名，「我认可的一条」 |
| 📎 参考（来源待考） | 30 | 有（去痕后） | 可以 | **「这是整理过的参考判断，原出处我没核到」**，不当作本人认可 |
| ⏳ 待确认 | 2 | **没有**（`view` 为空、`gated` 标记） | 只能给编号与状态 | 不说 |
| 📎 语料（九本书） | 216 | 有（每条带作者书名） | 可以 | 必须标作者 + 书名 |

**三档都能查，差别全在措辞上。** 参考档可用来说「有这么一种看法」，不能说「子贤认可」；九本书语料可用来说「这是 X《Y》里的观点」，不能说成本人判断。**没有一档能冒充本人原话。**

⏳ 待确认的观点根本不进对外数据层，所以任何调用方式、`--status all`、直接读 jsonl 都拿不到。完整原文只在本机留存，不随包分发。

## 二、三条调用路径

### 路径 A：学生问「你怎么看 X」

```
--topic / --scene / --keyword 检索（默认只出 ✅）
  → 取 1 条，把观点换成一句能问出来的问句
  → 落回 capabilities/ 对应模块，按四段给结论 + 这周第一件事
```

观点只占【为什么】里的一句。**停在观点上等于没答完。**

### 路径 B：要给结论配一个立场 / 写稿找金句

```
--keyword 或 --layer 检索 → 取 1-2 条
  → 按归属措辞连来源一起说
  → 说清它是判断不是规定；涉及规则一律给查法
```

一次最多两条。观点是佐料不是主食，**不连甩**。

### 路径 C：查出处 / 查库存

```
--scope corpus --book 或 --id   → 交出编号、作者《书名》、状态
--stats                        → 只给各状态数量，不返回任何观点
```

语料明确说成「引用源」，不说成本人判断。九本书的作者与书名在 `../data/00_索引.md`。

## 三、跟其他层怎么接力

| 场景 | 走哪 |
|---|---|
| 按学生原话的卡点快速换角度 | **思想层**的「问题-原子对照表」 → `../../../method/14_思想校准.md` |
| 全量检索、按主题/层次/场景查、查出处、查库存 | **本引擎** |
| 转述别人的话要判断能不能信 | `../../../method/01_命题审查.md`（引擎不替他审查） |
| 问规定、名额、时间、分数线 | `knowledge/制度/`，一律给查法，引擎不调 |
| 取完观点之后 | **必须回 `capabilities/` 给结论**，引擎不负责答案 |

**顺序不能反**：先判断问题成不成立、材料够不够，再取观点换角度，最后给结论。反过来就是把金句当答案。

## 四、归属措辞（对外）

| 类别 | 能说 | 不能说 |
|---|---|---|
| 口述 ✅ | 「我一直这么说」 | 「规定是」、拿去替本校文件作答 |
| 出版物 ✅ | 「这是从 X《Y》里提炼、我认可的一条」 | 不标出处、说成原创或自己的原话 |
| 📎 语料 | 「X《Y》里有个说法」 | 「我认为」「我一直这么说」 |
| 未登记 / ⏳ | 什么都不说 | 任何形式的引用 |

**标观点归属（作者 + 书名）是要求的；暴露「这套东西是怎么做出来的」仍然禁止。**

给最终用户的回答**不报编号**；编号只出现在引擎内部输出和索引里。

## 五、输出模板

```
【结论】一句话，不铺垫
【为什么】…（观点最多一句，连归属一起说）
【怎么做】这周能开始的 1-3 个动作
【代价】两条路各自的代价，或这条判断什么时候不成立
```

- 简单问题只给【结论】+【怎么做】
- 观点**不占独立段落**，不写成「下面是我的三条认知」
- 某段没内容就整段删掉，不写「暂无」
- 取到观点后必须写出它的**边界**：什么情况下不成立

## 六、什么算答完

| 算 | 不算 |
|---|---|
| 给了一条已认可观点 + 来源 + 一句能问出口的问句 + 这周的动作 | 念了三句金句 |
| 查出处给了作者、书名、状态 | 「好像是哪本书里说过」 |
| 没查到就直说没有，并给换关键词或换层的建议 | 用相近的语料凑一条 |
| 明确标出「这是判断，不是规定」 | 拿观点回答制度题 |

## 七、维护

`data/` 下三份与 `../data/00_索引.md` 由 `tools/build-atoms-engine.py` 从独立原子库生成，**统一生成、勿手改**。
原子库补齐来源/认可状态并点头转正后，重跑生成脚本（或 `sync-all.py`，它会自动调），新观点自动进入检索；第八道闸会校验生成物与真源一致、未认可条目没有观点原文、语料每条带作者书名。

**⏳ 不点头，不自动转正。** 这是收录铁律，不是技术限制。
