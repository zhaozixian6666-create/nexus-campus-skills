# 06 · 拆解与吸收

> 用途：拆一篇好论文、一份获奖 BP、一个优秀学长的简历、一条知识区视频、一堂好课。
>
> **"看过了"和"拆过了"是两件事。** 看是消费，拆是生产——只有拆完你能自己做一遍，才算吸收。

---

## 一、这个模块解决什么

大学生每天"学习"的方式：

> 刷了两小时知识区视频 → 觉得学到了很多 → 一周后什么都想不起来
> 看了一篇顶刊论文 → 觉得写得好 → 自己写的时候还是不会
> 看了一份国金 BP → 觉得厉害 → 自己做还是没思路

**问题不在看得少，在看的姿势是"消费"。**

消费的特征：**被动接收，有愉悦感，没有留下可复用的东西。**

**拆解的特征**：**主动提问，有阻力，产出一份能用的模板/清单/判断。**

**这个模块做的事：给一套拆解流程，让"看过"变成"能用"。**

---

## 二、核心判断

### 判断 1：拆解的目标不是"看懂"，是"能复用"

**这两者的差别很大。**

| 看懂 | 能复用 |
|---|---|
| "他这篇论文论证很严密" | "他用了'先给反例再推翻'的结构，我下次写讨论部分可以用" |
| "这个 BP 做得很好" | "他的第 3 页用了一个'成本对比表'替代大段文字，我可以照这个改" |
| "这个老师讲得清楚" | "他每讲一个概念，先给一个生活例子，再给定义。我讲东西可以学这个顺序" |

**检验方法**：**拆完之后，你能说出"下次我怎么做"吗？**

说不出来 → 只是看懂了，没拆。

### 判断 2：拆解要拆到「决策点」，不是「结果」

**这是最有价值的一条。**

一份好作品，表面是一堆"结果"（这个标题好、这张图好、这段话说得好）。**但结果不能复用，因为场景不同。**

**能复用的是决策点**：

> **他在这个地方，有哪几个选项？他为什么选了这个？**

**举例（拆一份获奖 BP 的产品页）**：

| 层 | 内容 |
|---|---|
| **结果**（不能复用） | 这页放了三张图 + 一段话 |
| **决策点**（能复用） | 他选择了"图多字少"。为什么？因为路演只有 5 分钟，评委看图比读字快。**但如果是书面评审（评委自己看文件），这个选择可能相反——需要更多文字说明** |

**所以你能复用不是"图多字少"，是**：

> **"看评审方式决定图字比例：口头路演偏图，书面评审偏字。"**

**规则**：**每拆一个点，问一句"他还有别的选择吗？为什么选这个？"**

答不出来，说明你拆的是结果，不是决策。

### 判断 3：拆解分三层，从外到内

| 层 | 拆什么 | 问什么 | 产出 |
|---|---|---|---|
| **L1 结构** | 骨架：分成几块、什么顺序 | 他为什么按这个顺序？换一个会怎样？ | 一个可套用的框架 |
| **L2 手法** | 具体技巧：句式、图表、过渡、节奏 | 这个技巧解决什么问题？什么场合适用？ | 一份手法清单 |
| **L3 判断** | 他做的取舍：为什么这里详、那里略 | 他的目标是什么？这个取舍服务于什么？ | **一套判断标准** |

**大多数人只拆到 L2**（记了几个技巧），所以用不出来——因为**技巧要放在结构里才有意义**。

**优先级**：**L3 > L1 > L2**。

**为什么 L3 最重要**：因为 L3 是"为什么这么选"，而 L1、L2 只是"选了什么"。**只有 L3 能迁移到你的场景。**

### 判断 4：拆一个不如拆三个

**拆一个作品，你只能看到"这个作品的做法"。拆三个同类作品，你能看到"这个品类的规律"。**

| 数量 | 能看到 | 局限 |
|---|---|---|
| 1 个 | 他的具体做法 | 分不清"这是规律"还是"这是他的个人风格" |
| 3 个 | **共性**（三个都有的，是规律） | 能形成可复用的判断 |
| 5 个以上 | 规律 + **变体**（哪些地方可以不同） | 能形成自己的风格 |

**具体做法**：拆三个之后，做一张表：

| 特征 | 作品 A | 作品 B | 作品 C | 共性是？ |
|---|---|---|---|---|
| 开头方式 | 数据 | 故事 | 问题 | **都给了一个"钩子"** |
| 结构 | 三段 | 四段 | 三段 | **都是结论先行** |
| 结尾 | 号召 | 画面 | 数字 | **都不一样（可以自由）** |

**这张表的价值**：它告诉你**哪些必须学（共性）、哪些可以自由（差异）**。

**很多人拆解失败，就是因为只拆一个，把别人的个人风格当成了规律。**

### 判断 5：拆完必须做一次「迁移测试」

**这是唯一能验证"是否真的学会"的方法。**

**迁移测试**：

> **用你拆出来的东西，在完全不同的题材上做一遍。**

**举例**：

- 拆了一篇讲材料的论文的结构 → 用这个结构写一篇讲营销的课程论文
- 拆了国金 BP 的产品页 → 用这个思路做你社团的招新海报
- 拆了一个知识区视频的开头 → 用这个开头讲你的专业课知识点

**能迁移 → 真的学会了**
**不能迁移 → 你只是记住了那个作品的样子**

**这一步 90% 的人不做。** 因为它费劲，而且会暴露"其实没学会"。

### 判断 6：笔记不等于拆解

**这是最普遍的误解。**

| 笔记 | 拆解 |
|---|---|
| 摘抄原话 | 问"他为什么这么说" |
| 记"这个观点很好" | 记"这个观点在什么条件下成立" |
| 三页纸，很整齐 | 半页纸，全是问题 |
| 有愉悦感 | 有阻力感 |

**为什么笔记会产生"学会了"的错觉**：因为抄写有即时反馈（字很整齐、内容很多），大脑会把它当成"进步"。

**但抄下来的东西，你从来没用自己的话重说过。**

**规则**：**拆解笔记里，必须有一半是"我的问题"和"我的判断"，不能全是"他的内容"。**

## 三、操作流程

### Step 1：选材（拆三个同类）

**不要随机选。三个要满足**：

- 同一个品类（都是国金 BP / 都是顶刊论文 / 都是答辩）
- **至少一个是公认优秀的**（有客观标准：获奖、被引、被推荐）
- 题材不要完全相同（否则看不出变体）

### Step 2：先整体看一遍，不记笔记

**第一遍只做一件事：判断它的核心是什么。**

```
这份东西，只让我记住一件事的话，是哪件？
```

**为什么第一遍不记笔记**：记笔记会让你陷进细节，看不到整体。

### Step 3：第二遍拆结构（L1）

```
1. 它分成几块？
2. 每块承担什么任务？
3. 这个顺序，如果换一个会怎样？
```

**产出**：一张骨架图（几块 + 顺序 + 每块的任务）

### Step 4：第三遍拆手法（L2）

**只拆"你做不到的部分"**，不要全拆。

```
1. 哪个地方我做不到？
2. 他用了什么手法做到的？（具体到句子/图表/过渡）
3. 这个手法解决什么问题？
```

**产出**：3-5 条手法（每条要写清"解决什么问题"）

### Step 5：拆判断（L3）——最重要

**对每个关键位置问三个问题**：

```
1. 他在这里还有别的选择吗？（列 2-3 个）
2. 他为什么选了这个？
3. 如果换成别的，会有什么区别？
```

**产出**：一套判断标准（"在 X 情况下选 A，在 Y 情况下选 B"）

### Step 6：做共性表（三份对比）

把三个作品按同一维度对比，标出**共性**和**差异**。

**共性 = 必须学的规律；差异 = 可以自由发挥的地方。**

### Step 7：迁移测试

**换一个完全不同的题材，用你拆出的框架做一遍。**

做完对照：哪里顺、哪里卡？

**卡住的地方，就是你没真拆懂的地方。**

### Step 8：写成一页可用的东西

```
【拆解：XX 类作品】

## 骨架（必学）
1. ……
2. ……

## 判断标准（必学）
- 当 ___ 时，选 ___；当 ___ 时，选 ___

## 手法（可选，看情况）
- ___：解决 ___ 问题

## 可以自由的地方
- ……

## 我迁移过的例子
- 用这个框架做了 ___，效果是 ___
```

**这一页才是产出。** 前面的阅读过程不是。

## 四、大学场景实例

### 实例 1：拆一篇顶刊论文

| 层 | 拆到的东西 |
|---|---|
| **L1 结构** | 摘要（问题+方法+结果一句话）→ 引言（现状→缺口→本文做什么）→ 方法（能复现）→ 结果（主图+对照）→ 讨论（机制+局限） |
| **L2 手法** | ① 引言最后一段永远是"本文的贡献有三点"（给读者地图）② 结果部分每张图下面都有一句"这说明……"（不让读者自己解读）③ 局限写在讨论最后一段，三条，具体 |
| **L3 判断** | 引言里"缺口"的写法：不是"没人研究过"，是"已有研究在 X 条件下成立，但在 Y 条件下失效"。**因为"没人研究过"通常意味着不重要，而"在某条件下失效"才是真缺口** |
| **迁移** | 把这个"缺口写法"用在自己的课程论文上：不要写"这方面的研究较少"，写"已有研究多关注 A，但 B 情况下的表现尚不清楚" |

**关键**：L3 那一条最有价值，因为它教的是**怎么找一个站得住的研究缺口**，而不只是"论文长什么样"。

### 实例 2：拆三份国金 BP

| 维度 | BP-A（技术型） | BP-B（服务型） | BP-C（公益型） | 共性 |
|---|---|---|---|---|
| 第 1 页 | 一句话 + 大图 | 一个问题 + 数据 | 一个故事 + 照片 | **都有一个"钩子"，不用目录页开场** |
| 问题页 | 技术指标对比 | 用户痛点问卷 | 受益者访谈 | **都用"外部证据"证明问题真实**（不是自己说） |
| 方案页 | 架构图 | 流程图 | 场景照片 | **都用了图，但图类型不同（跟着项目性质走）** |
| 数据页 | 实验室数据 | 运营数据 | 覆盖人数 | **都有数字，且都给了参照系** |
| 团队页 | 放最后 | 放最后 | 放最后 | **都在最后** |
| 财务页 | 详细 | 详细 | 简略（有资助） | **强制性的，但详略可以调** |

**共性结论（可复用）**：
1. 开头必须有钩子，不能从目录开始
2. 问题真实性靠外部证据，不靠自己陈述
3. 图的形式跟着项目性质走（技术型用架构图，服务型用流程，公益型用场景）
4. 数字必须带参照系
5. 团队页放最后

**差异结论（可自由）**：财务页详略、故事 vs 数据开场、团队页是否突出导师。

### 实例 3：拆一个学长的简历

**不要抄他的内容**（你的经历不同），**要拆他的判断**。

| 拆什么 | 他的做法 | 判断（可复用） |
|---|---|---|
| 顺序 | 项目在前，教育在后 | **因为他最想证明"能做事"，不是"成绩好"**。如果我成绩是优势，顺序反过来 |
| 项目描述 | 每条"动作 + 数字 + 结果" | **必须这样，否则面试官问不下去** |
| 技能栏 | 只写了 4 项，都很具体 | **写能验证的，不写"熟练使用 Office"** |
| 篇幅 | 一页 | **应届生一页，多余的删** |
| 照片 | 没有 | **技术岗不需要，某些岗位需要** |

**关键**：**拆的是"他为什么这么排"，不是"他写了什么"。**

### 实例 4：拆一条知识区视频

| 层 | 内容 |
|---|---|
| **L1 结构** | 0-15 秒：反常识结论 → 15-60 秒：为什么大家会误解 → 60-180 秒：三个证据 → 180-240 秒：怎么办 → 最后 10 秒：一句话总结 |
| **L2 手法** | ① 每 30 秒有一个"字幕重点句" ② 举例都用"我有个朋友"（降低距离感） ③ 数字都换算成"相当于……" |
| **L3 判断** | 开头用"反常识"而不是"重要性"。**因为"这很重要"是所有人都在说的，"你一直以为的其实是错的"才会让人停下来** |
| **迁移** | 把这个开头逻辑用在课堂展示上：不说"这个话题很重要"，说"大部分人以为 X，其实 Y" |

**注意**：这个视频讲的内容可能是错的。**拆解拆的是"怎么讲"，不是"讲得对不对"。内容对错要去命题审查审。**

## 五、反例与边界

### 边界 1：不是所有东西都值得拆

**拆解很费时间**（一份 BP 拆完 1-2 小时）。**只拆你马上要用的。**

**判断标准**：**我下个月会在什么场景下用到这个框架？** 说不出来 → 别拆，收藏就好（或者干脆不收藏）。

### 边界 2：拆解不能替代原创

**有人拆多了，变成"拼装工"**——这里学一点，那里学一点，拼出来一个四不像。

**拆解的正确用途**：**建立判断标准，然后用标准做自己的东西。**

**不是**：把别人的零件搬过来组装。

**区别**：前者产出"我知道什么场合该怎么做"；后者产出"我把三段别人的话缝在了一起"。

### 边界 3：不能拆到"什么都拆不出"

有些作品确实没什么可拆的（普通水平的作业、随便做的 PPT）。

**拆它的价值在于"看出哪里不好"**，而不是"学到什么"。

**规则**：**拆优秀作品学"该怎么"，拆普通作品学"不该怎么"。** 两者都有用，但目标不同。

### 边界 4：不要为了拆而拆

有一种病：看什么都要"拆解分析"，最后失去了正常欣赏的能力。

**看电影要拆结构、听歌要拆编曲、看文章要拆套路**——这很累，而且会毁掉很多乐趣。

**规则**：**只在"我要做同类的东西"时拆。** 其他时候，正常看就好。

### 边界 5：拆解会遇到"看起来对但其实是运气"

有些作品做得好，是因为运气（赶上风口、评委偏好、对手太弱）。

**你怎么知道**：看他是不是**连续**做出好东西。

**规则**：**拆对象优先选"做出过多次好作品的人"**，而不是"有一次爆火的人"（这和对标法的判断 1 一致）。

### 边界 6：不要拆到丧失自己的判断

拆多了，会形成"这个做法是标准"的错觉。

**但很多"标准做法"是有条件的**（某个年代、某类评审、某个平台）。

**规则**：**拆出规律之后，问一句"这个规律在什么条件下失效"。** 答不出来，说明你还没拆到 L3。

## 六、常见误用

| 误用 | 表现 | 后果 |
|---|---|---|
| **只拆结果不拆决策** | "他这个标题好" | 换个场景就不会用了 |
| **只拆手法不拆结构** | 记了十个技巧 | 用的时候拼不起来 |
| **只拆一个** | 把个人风格当规律 | 学歪 |
| **只记笔记不拆** | 抄了三页，很整齐 | 一周后全忘 |
| **不做迁移测试** | 觉得学会了 | 真做的时候发现不会 |
| **拆完不用** | 拆了十份 BP，自己做还是没思路 | 拆解变成新的消费 |
| **拆成拼装工** | 到处搬零件 | 四不像 |
| **什么都拆** | 看电影也拆套路 | 失去乐趣 |

## 七、和其他模块的关系

```
自学法（学一个领域）
对标法（学一个人）
拆解与吸收 拆解（拆一件具体作品）  ← 最小的学习单元
```

- **拆解与吸收是自学法、对标法的执行手段**：自学法说"找三个范本"，怎么拆？用拆解与吸收。对标法说"拆 L1/L2/L3"，具体怎么操作？用拆解与吸收的三层
- **拆解与吸收 → 命题审查**：拆出来的结论，要过命题审查（"他这个做法真的有效吗，还是运气？"）
- **拆解与吸收 → 写清楚/结构与开场/讲进去**：拆写作作品用写清楚的规则看句子，拆汇报用结构与开场看结构，拆演讲用讲进去看表达
- **拆解与吸收 → 决策档案**：拆解产出的一页"判断标准"，存进决策档案或知识库（知识库自建）
- **和 `../knowledge/认知/06_大学案例复盘.md` 的分工**：大学案例复盘拆的是**自己做过的事**（复盘），拆解与吸收拆的是**别人的作品**（学习）。**结构相似，对象不同**

## 八、自检

1. 拆完之后，我能说出"**下次我怎么做**"吗？
2. 我拆的是**决策点**（他为什么这么选），还是**结果**（他做了什么）？
3. 三层都拆了吗？还是只拆了手法（L2）？
4. 拆了几个？（只拆一个 = 容易把个人风格当规律）
5. 做了共性表吗？哪些是规律、哪些可以自由？
6. 做**迁移测试**了吗？换一个题材做过一遍吗？
7. 我的笔记里，"我的问题/判断"占一半吗？（全是摘抄 = 只是笔记）
8. 有没有踩到六条边界？（不必要的拆 / 变拼装工 / 拆不出东西 / 什么都拆 / 拆运气型作品 / 丧失自己判断）

## 九、来源与定位

- 使用的公开概念：刻意练习中的"心理表征"（拆解是在建立可复用的表征）、对比学习
- 本模块的判断对外说「这是我的判断」；讲边界的说「按这套方法推是这样」。
- ⚠️ **拆解拆的是"怎么做的"，不判断"对不对"**。内容真实性用 `../method/01_命题审查.md`
