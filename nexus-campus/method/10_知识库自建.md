# 10 · 知识库自建

> 用途：建一个自己的文件夹，让「存进去的东西，三个月后还能找回来、还能用」。
>
> **收藏不等于拥有。** 存了 500 篇笔记、8 个 G 的课件、三个版本的简历——用的时候一个都找不到，等于没有。

---

## 一、这个模块解决什么

大学生的资料状态，通常是这样的：

```
桌面/
├── 新建文件夹/
├── 新建文件夹(2)/
├── 课件/（里面 60 个文件，命名是"第1章.pptx"到"第12章(1).pptx"）
├── 简历.docx
├── 简历-改.docx
├── 简历-最终.docx
├── 简历-最终-真的最终.docx
└── 各种下载的东西
```

**三个具体后果**：

1. **找不到**：知道"我存过一份很好的笔记"，翻了 20 分钟没找到，最后重新做
2. **不知道以哪个为准**：三个版本简历，投的时候犹豫，投错了版本
3. **存了不用**：收藏夹 800 条，实际回看过的不到 10 条

**这个模块做的事：给一套最小结构，让资料能被找回来、能判断版本、能判断是否过期。**

---

## 二、核心判断

### 判断 1：知识库的成败在「能不能找回来」，不在「收集了多少」

这是第一原理，也是最容易被忽略的。

**收藏这个动作本身没有价值。** 有价值的是"三个月后我需要它时，能在 60 秒内找到"。

**检验方法**：随便说一个你三个月前存的东西，现在能在 60 秒内找到吗？

- 能 → 你的库是可用的
- 不能 → 那是个仓库，不是知识库

**推论**：**判断一个资料要不要存，标准不是"以后可能有用"，是"以后我能在什么场景下需要它"。** 说不出场景的，不存。

### 判断 2：必须有一条规则回答「以哪个为准」

这是最实用的一条，也是最多人缺的。

**典型问题**：

- 三个版本的简历，投哪个？
- 笔记有纸质、有 iPad、有电脑文档，看哪个？
- 保研细则有学院版、学校版、去年的、今年的，按哪个？

**规则必须写下来，而且只能有一条**：

```markdown
## 以哪个为准

- 简历：以 `求职/简历_v3_2026-09.docx` 为准，其余进 90_归档
- 保研细则：以学院官网「2027 届推免实施细则」为准；学校版只作参考
- 课程笔记：以 `课程/XX/笔记_主.md` 为准，纸质版只记灵感
```

**为什么必须有**：

没有这条规则，你每次都要重新判断"这个是不是最新的"，而这个判断每次都可能错。

**写在哪**：知识库根目录一个文件，叫 `../knowledge/原子库/data/00_索引.md` 或「以哪个为准.md」。

**规则制定的三个要求**：

| 要求 | 说明 |
|---|---|
| **只有一个权威源** | "两个都参考"等于没有权威源 |
| **写清版本号或日期** | 不能只写文件名，会改名 |
| **写清什么情况要更新** | 比如"每学期开学更新一次" |

### 判断 3：目录职责要写清「放什么、不放什么」

只写"这层放什么"不够，**必须写"不放什么"**。

因为人会不自觉地把东西放到"最像的那个"文件夹，而"最像"往往不是"应该"。

**每个目录一个 README，两句话**：

```markdown
# 03_课程

## 放什么
本学期的课件、作业、真题、我的笔记。

## 不放什么
- 参考书 PDF → 放 05_资料
- 和课程无关的网课 → 放 06_自学
- 上学期的（已结课）→ 放 90_归档
```

**"不放什么"这一条，能减少 80% 的乱放。**

### 判断 4：命名是检索的唯一入口

文件夹分类解决"大类"，**命名解决"具体是哪个"**。

**坏命名的四种**：

| 类型 | 例 | 问题 |
|---|---|---|
| **无信息** | 「新建文档.docx」、「未命名.md」 | 完全无法检索 |
| **只有主题** | `简历.docx` | 不知道哪一版 |
| **只有时间** | 「20260915.md」 | 不知道是什么 |
| **符号混乱** | `最终版(1)(2) - 副本.docx` | 排序混乱 |

**好命名的公式**：

```
日期_主题_状态.扩展名

例：
2026-09-15_简历_投产品岗.md
2026-11-02_保研细则_学院版.md
2026-10-20_竞赛_答辩稿_v3.md
```

**为什么日期放最前**：文件管理器默认按名字排序，日期在前 = 自动按时间排。

**为什么状态写清**：`v3`、`最终`、`草稿`、`待核实`——这些词决定了你会不会用它。

### 判断 5：每个知识单元要能独立成立

一条笔记、一份文档，如果脱离上下文就看不懂，那它就是废的。

**检验方法**：三个月后你打开这个文件，**不看任何别的文件**，能看懂吗？

**改前（依赖上下文）**：

> "老师说这个很重要，要考。另外那个方法的误差比较大，注意一下。"

**改后（独立成立）**：

> "《材料物理》第 6 章，老师明确说'晶格振动'必考（2026-10-15 课上）。
> 谢乐公式算晶粒尺寸时，晶粒 >100nm 误差显著增大（教材 P187），考试若给大晶粒数据要指出这点。"

**差别**：后者带**出处**（哪门课、哪天、哪本书哪页）+ **具体内容**。

**规则**：每个知识单元至少要有 —— **出处 + 内容 + 它解决什么问题**。

### 判断 6：知识会过期，必须标核实日期

**这是大学生最容易踩的坑**，尤其是规则类信息。

| 信息类型 | 过期速度 |
|---|---|
| 保研/推免细则 | **一年一变**，且可能中途改 |
| 竞赛时间、赛制 | 一年一变，有的两年一届 |
| 招聘要求、薪资 | 半年一变 |
| 软件操作、工具用法 | 一年到三年 |
| 学科基础概念 | 基本不变 |

**规则**：**凡是规则类、时间类信息，必须写"核实于 YYYY-MM-DD"，并注明"以官网为准"。**

> ❌ "保研要求绩点前 10%"
> ✅ "保研要求绩点前 10%（核实于 2026-09，来源：学院 2026 年推免细则 PDF 第 3 页。**2027 年可能调整，用前必查官网**）"

**为什么这条重要**：一条过期的信息，比没有信息更危险——**你会按它做决定**。

## 三、操作流程

### Step 1：先定目录（不超过 8 个）

**原则：按「你会怎么找」分，不按「东西是什么」分。**

```markdown
我的知识库/
├── 00_索引.md          ← 以哪个为准 + 导航
├── 01_课程/            本学期在上的
├── 02_项目/            竞赛、实习、科研
├── 03_求职/            简历、面经、岗位
├── 04_认知/            读过的、想过的、方法
├── 05_资料/            参考书、PDF、工具
├── 06_自学/            学校不教但在学的
└── 90_归档/            结课的、过期的、旧版本
```

**为什么不超过 8 个**：超过 8 个，你会开始犹豫"这个放哪"，然后随便放一个。

**`90_归档` 是最重要的一个**：它让你敢于把旧东西挪走，而不用删。

### Step 2：写 `../knowledge/原子库/data/00_索引.md`

这一页要解决三件事：

```markdown
# 我的知识库

## 一、以哪个为准（最重要）
| 资料 | 权威文件 | 什么情况更新 |
|---|---|---|
| 简历 | 03_求职/简历_v3_2026-09.md | 每次投递前 |
| 保研细则 | 02_项目/保研/2027细则_学院版.pdf | 每年 9 月 |
| 课程笔记 | 01_课程/XX/笔记_主.md | 每周 |

## 二、目录职责
（每个目录一句话 + 不放什么）

## 三、快速查找
- 我要找保研的东西 → 02_项目/保研/
- 我要找简历 → 03_求职/
- 我要找以前的想法 → 04_认知/

## 四、维护规则
- 每月最后一天：把结课的、过期的挪进 90_归档
- 每学期开学：更新保研/竞赛相关文件，标新的核实日期
```

**这一页是整个库的大脑。** 没有它，其他都是文件夹。

### Step 3：存东西时的三个动作

每次存一个新东西，做三件事：

| 动作 | 做什么 |
|---|---|
| **1. 定场景** | 我以后在什么情况下会需要它？（说不出来 → 不存） |
| **2. 改名字** | 按 `日期_主题_状态` 改 |
| **3. 加头信息** | 出处、核实日期、它解决什么问题 |

**第 1 步是过滤器**，能挡掉 70% 的无用收藏。

### Step 4：每月清理（20 分钟）

三件事：

1. **挪归档**：结课的、过期的、旧版本的 → `90_归档`
2. **查失效**：`../knowledge/原子库/data/00_索引.md` 里的路径还对吗？
3. **查重复**：有没有同一件事存了三份？

**不清的后果**：三个月后，库里 80% 是废的，你会开始不想打开它。

### Step 5：用的时候先查索引

**养成一个习惯**：需要某个东西时，**先打开 `../knowledge/原子库/data/00_索引.md`**，而不是直接在文件夹里翻。

**为什么**：翻文件夹靠记忆，查索引靠结构。记忆会错，结构不会。

## 四、大学场景实例

### 实例 1：保研资料库

**没有结构的状态**：
> 微信收藏里 20 条、电脑里 5 个 PDF、纸质打印 3 份，不知道哪份是新的。

**有结构的状态**：

```markdown
02_项目/保研/
├── README.md
├── 2027细则_学院版.pdf        （核实 2026-09-15）
├── 2027细则_学校版.pdf        （参考用，学院版优先）
├── 往年录取名单_2024-2026.xlsx
├── 加分项清单_我的.md          ← 我自己的情况对照
└── 时间线.md                  ← 关键节点
```

**README.md 写什么**：

```markdown
# 保研

## 以哪个为准
学院版细则（2027细则_学院版.pdf）。学校版只用于对照，冲突时以学院版为准。

## 不放什么
- 考研资料 → 02_项目/考研/
- 学长经验贴 → 04_认知/经验/

## 关键提醒
细则每年 9 月更新。用之前必须去官网确认有没有新版。
```

### 实例 2：简历版本管理

**改前**：
```
简历.docx
简历-改.docx
简历-最终.docx
简历-最终-真的最终.docx
简历-投产品岗.docx
```

**改后**：
```
03_求职/
├── 简历_主版本_2026-09.md       ← 权威版
├── 简历_产品岗_2026-09.md       ← 基于主版本改的定向版
├── 简历_运营岗_2026-10.md
└── 90_归档/（旧版本全在这）
```

**`../knowledge/原子库/data/00_索引.md` 里写**：

> 简历以「简历_主版本_2026-09.md」为准。每次投递前先改主版本，再复制出定向版。定向版不进权威列表。

**关键洞察**：**版本管理的核心不是"记得哪个最新"，是"让最新那个有个唯一的名字"。**

### 实例 3：课程笔记

**改前**：每节课一个 Word，命名"第3章.docx"，散在桌面。

**改后**：

```markdown
01_课程/材料物理/
├── README.md
├── 笔记_主.md          ← 所有课的内容，按章节顺序，一个文件
├── 例题/               ← 每类题一个文件
└── 真题/               ← 往年卷
```

**为什么笔记合成一个文件**：

- 找东西时用 `Ctrl+F`，比开 12 个文件快
- 能看出章节之间的关系
- 复习时不会漏

**每个知识点写成这样**：

```markdown
## 6.3 晶格振动
**出处**：教材 P167-180；2026-10-15 课
**必考**：老师明确说了（课上原话："这个必考"）
**一句话**：原子在平衡位置附近振动，形成格波，量子化后是声子
**易错**：声子不是真实粒子，是准粒子，不守恒
**例题**：习题 6-7、6-9
```

### 实例 4：认知积累（最容易被浪费的一类）

大学生每天看到很多有启发的东西，然后忘了。

**改后**：

```markdown
04_认知/
├── 想法_我的.md        ← 我自己想的
├── 摘录_别人的.md      ← 看到的，必须标来源
└── 冲突_待想.md        ← 两条打架的，还没想清的
```

**规则（很重要）**：

**自己的想法和别人的摘录必须分开。** 混在一起，三个月后你会把自己想的当成别人说的，或者把别人说的当自己想出来的。

**摘录必须带来源**：

> ❌ "延迟满足很重要"
> ✅ "延迟满足很重要（米歇尔棉花糖实验，1960s；但 2018 年 Watts 的重复实验发现效应小很多，且受家庭背景影响 —— 所以这条要打折）"

## 五、反例与边界

### 边界 1：不要为建库而建库

有些人把建知识库本身当成目标，花一周设计目录、搞插件、写模板，**然后不用**。

**规则**：**先有需要，再建结构。** 没有 20 个文件，不需要目录；没有反复找不到东西，不需要索引。

**信号**：如果你在纠结"用 Notion 还是 Obsidian 还是语雀"，说明你还没到需要工具的阶段。**一个文件夹 + 一个 txt 就够。**

### 边界 2：不是所有东西都值得存

**"以后可能有用"是最危险的判断。** 它会让你的库变成垃圾场。

**正确的判断**：**"我下个月会在什么场景下用它？"** 说不出来，不存。

**已经存了的怎么办**：不用清理，让它烂在 `90_归档`。**清垃圾的时间成本，通常高于垃圾本身的成本。**

### 边界 3：不要追求完美分类

有些人一个文件放哪纠结十分钟。

**规则**：**放一个"大概对"的地方，然后在索引里留一行"我要找它去这里"。**

**分类是给检索用的，不是给审美用的。** 能找到就行。

### 边界 4：系统不要超过两层

三层以上的目录，你会开始记不住结构。

**规则**：**最多两层。第三层用命名解决**（`01_课程/材料物理/` 里用"笔记_主.md"而不是再建一个"笔记"文件夹）。

### 边界 5：不要把别人的体系照搬过来

网上有很多"PARA 法""卡片盒笔记法""第二大脑"——**这些是别人的，不一定适合你**。

**用法**：看它们的**原则**（比如"以哪个为准"），不要抄**结构**。

**判断标准**：一个方法如果让你花超过 2 小时搭建，它就不适合现在的你。

### 边界 6：涉及隐私的东西单独放

成绩单、身份证、家庭信息、聊天记录——**不要放在随手会打开、会同步的库里**。

**规则**：敏感资料单独一个文件夹，不云同步，或者加密。

## 六、常见误用

| 误用 | 表现 | 后果 |
|---|---|---|
| **收藏即拥有** | 存了 800 条，一条没看 | 制造"我在学习"的幻觉 |
| **没有"以哪个为准"** | 三个版本简历 | 投错版本 |
| **命名无信息** | `新建文档(3).docx` | 完全检索不到 |
| **目录超过 8 个** | 每次放东西都犹豫 | 最后随便放 |
| **不标核实日期** | "保研要前 10%" | 按过期信息做决定 |
| **想法和摘录混着** | 分不清谁说的 | 三个月后认错来源 |
| **只建不用** | 结构很漂亮，从不打开 | 白费功夫 |
| **从不清理** | 库里 80% 是废的 | 不想打开它 |

## 七、和其他模块的关系

- **知识库自建是决策档案的底座**：决策档案（决策档案）本身就是一个小知识库，用知识库自建的规则建
- **知识库自建 → 命题审查**：存进来的观点，先过命题审查，再标"来源 + 可信度"
- **知识库自建 → 对标法**：对标对象的资料存进来时，三层拆解（L1/L2/L3）的结论也存
- **知识库自建 → 写清楚**：存进来的笔记要"独立成立"，写法用写清楚
- **和 `../knowledge/README.md` 的关系**：那是**这个 Skill 内部**的知识包结构，知识库自建是**用户自己**的知识库方法。**两者规则一致，但服务对象不同**

## 八、自检

1. 随便说一个三个月前存的东西，60 秒内能找到吗？
2. `../knowledge/原子库/data/00_索引.md` 里有"以哪个为准"这一节吗？每个关键资料都写了吗？
3. 目录超过 8 个了吗？（超过 = 该合并）
4. 文件名是 `日期_主题_状态` 吗？
5. 每条笔记不看别的文件，能看懂吗？（出处、内容、解决什么问题）
6. 规则类信息标了"核实于 YYYY-MM-DD"吗？
7. 自己的想法和别人的摘录，分开了吗？
8. 上次清理是什么时候？（超过一个月 = 该清了）
9. 有没有踩到六条边界？（为建而建 / 什么都存 / 纠结分类 / 超过两层 / 照搬别人体系 / 隐私没隔离）
