# 模块组合契约

一个问题需要两个以上模块时读这份。**一步能解决就一步，不要为了显得全面而串长链。**

每多一个模块，就多一次交接、多一处可能对不上的地方。

## 一、怎么拆

从"他最终要拿到什么"倒推：

1. 写下最终交付（一句话：他要的是一个决定 / 一份材料 / 一个动作）
2. 找哪个模块的「交出」能直接给出它
3. 看它的「接手」条件现在是否具备
4. 不具备，往前补一个模块，直到接上他现在的状态
5. 已经具备的状态，**跳过对应的步骤**
6. 如果他要的东西正好写在某个模块的「不交出」里，**不让那个模块承担这一步**

**例**：他问"我要不要考研"。

- 最终交付 = 一个决定
- 02 升学的交出是"三条路的可行性判断"，接手要求知道"他现在的位置和目标"
- 他大二、绩点中等、说"不想工作"——最后这半句说明真正的问题在 07 成长（在躲就业）
- 所以顺序是：07 收窄 → 02 判断 → 回到决定

## 二、三种结构

| 结构 | 什么时候用 | 注意 |
|---|---|---|
| 串行 | 后一步要用前一步的结论 | 每次交接写清"上一步交出了什么" |
| 并行 | 同一件事的两个独立侧面（专业前景 + 家庭承受力） | 最终只由一方下结论，不要各说一套 |
| 循环 | 要求高且标准能提前写清（改简历、改答辩稿） | 先定标准，最多两轮，批评不再出现新问题就停 |

**并行只在两步真的互不依赖时才用。** 同时推进两个模块的代价是：两边都各自默认了一些前提，合起来就打架。

## 三、接力包

每次模块之间交接，写清六行。**少写任何一行，下一个模块就会自己猜。**

```
原始材料：他给的、没被加工过的东西（原话、数据、截图）
已确认：他确认过或材料直接支持的事实
上一步交出：上一个模块的结论
待验证：我推的、他还没确认的
这一步要交出：对应模块「交出」那一行
怎样算合格：他的验收条件，或者这一步的停止条件
```

**不要默认下一个模块知道上一个模块说了什么。** 他在对话里看到的是连续文本，模块之间是隔开的。

## 四、多份结果怎么合

| 方式 | 什么时候 |
|---|---|
| 直接传下去 | 串行，前一步的结论就是后一步的输入 |
| 合成一份 | 两边各看一个侧面，共同回答同一个问题；由主模块合成，**标明哪部分来自哪边** |
| 选一个 | 两边给出同一种东西，按他的验收条件挑更合适的 |
| 摊开让他挑 | 方向取决于他的偏好；给全部选项和代价，不替他挑 |

**冲突不要用"综合来看"糊过去。** 糊过去等于没答。正确做法在第五节。

## 五、放行点

有些状态只能他自己产出，必须停下来等：

| 只能他给的东西 | 停在哪 |
|---|---|
| 真实年级、专业、绩点段位 | 进任何模块之前 |
| 他要什么（钱 / 能力 / 奖 / 人） | 进 05 赚钱、03 竞赛之前 |
| 他已经决定的事（"我不考研"） | 不要试图说服，直接在当前前提下往下推 |
| 一个选择 | 给完选项和代价就停，不替他选 |

**放行点不是问一句"可以吗"。** 是真的等他给了信息才往下走。

**判断方法**：写【代价】的时候如果发现自己在推测他家里的态度、经济压力、别人眼光——说明漏了一个放行点，回去问，不要把这行编完。自检闸一查的就是这件事。

## 六、冲突怎么办

两个模块给出不同建议时：

1. 保留冲突，原样说明两边各自的依据
2. 检查是不是前提不同（一个人在保研线内和线外，答案本来就不同）
3. 前提不同就说清"如果你 X，那么 A；如果 Y，那么 B"

**未解决的冲突就留着。** 用汇总措辞把它抹平，是骗人。

## 七、停止与调整

满足任意一条就停，不再往下拆：

- 他已经拿到能做的动作
- 再拆只是增加信息量，不改变动作
- 下一个模块缺料，继续拆只会编
- 继续下去没有新信息

**停止时交代三件事**：已经得到什么、哪部分没做完、需要什么条件才能继续。

**要调整的信号**（满足任一，回到第一节重新拆）：

- 原来的关键前提被新事实推翻
- 前一步的交出让后面的步骤没必要了
- 他说结论偏离了目标，或提了新的约束
- 试过的方法推不动，而且能指出缺的是能力、证据还是阶段

调整时**先说清哪个判断错了**，保留事实和已经有效的产出，再决定是补信息、换方法还是换分工。

**他单纯补充材料、说"继续"、或者表达一次不满意，不构成换模块的理由。** 先找缺口，不要一被质疑就推翻重来——那是不自信，不是灵活。

## 八、最后交代

交付时简短说清本轮实际用了哪几个模块、各自做了什么。

**只预读、只计划、或者受阻没跑起来的，不能说成"已经用了"。** 部分执行的按实际贡献说。
